## 流程分支详解

### 分支 1: 投标文件检查流程 (Check Flow - check_workflow)

**路由条件**: `workflow_type = "check"`

**流程节点**:
1. `tender_doc_parse` - 招标文件解析（共享）
2. `route_by_workflow` - 条件路由节点
3. `bid_doc_parse` - 投标文件解析
4. **汇聚节点 1** (Merge Node 1) - 汇聚投标文件解析的输出，分发到六个并行检查任务
5. 六维并行检查：
   - `invalid_items_check` - 废标项检查（大语言模型）
   - `commercial_score_check` - 商务得分检查（大语言模型）
   - `technical_plan_check` - 技术方案检查（大语言模型）
   - `indicator_response_check` - 指标应答检查（大语言模型）
   - `technical_score_check` - 技术得分检查（大语言模型）
   - `bid_structure_check` - 文件结构检查（大语言模型）
6. `modification_summary` - 修改建议汇总（大语言模型）

**关键特点**:
- 六个检查任务并行执行，提高效率
- 每个检查任务独立使用大语言模型进行分析
- 所有检查结果汇总到 `modification_summary` 节点
- 输出包含详细的修改建议和评分

---

### 分支 2: 投标材料生成流程 (Generate Flow - generate 分支)

**路由条件**: `workflow_type = "generate"`

**流程节点**:
1. `tender_doc_parse` - 招标文件解析（共享）
2. `route_by_workflow` - 条件路由节点
3. `tender_requirements_parse` - 招标要求解析（大语言模型）
4. **人工节点** (Human Node) - 人工审核点，用户可在此介入审核或调整要求
5. **汇聚节点 2** (Merge Node 2) - 汇聚人工节点的输出，分发到四个并行检索任务
6. 四路并行检索：
   - `commercial_kb_search` - 商务知识库检索（本地知识库）
   - `technical_kb_search` - 技术知识库检索（本地知识库）
   - `commercial_web_search` - 商务互联网搜索（联网搜索）
   - `technical_web_search` - 技术互联网搜索（联网搜索）
7. **汇聚节点 3** (Merge Node 3) - 汇聚四个检索任务的输出
8. 并行材料生成：
   - `commercial_material_generate` - 商务材料生成（大语言模型）
   - `technical_material_generate` - 技术材料生成（大语言模型）
9. **汇聚节点 4** (Merge Node 4) - 汇聚两个材料生成任务的输出

**关键特点**:
- 包含人工节点，支持人工审核和干预
- 四路并行检索（本地知识库 + 互联网搜索）
- 材料生成基于检索结果和招标要求
- 支持同时生成商务和技术材料

**核心组件**:

1. **KnowledgeIndexer** - 索引管理工具
   - `scan_and_index_files` - 扫描 datafiles 目录并更新索引
   - `create_file_index` - 为单个文件创建索引
   - `update_file_index` - 更新已有文件的索引
   - `delete_file_index` - 删除文件的索引
   - `edit_index` - 编辑索引元数据
   - `search_knowledge` - 搜索知识库

2. **KnowledgeScheduler** - 定时调度器
   - 定时扫描 datafiles 目录
   - 默认间隔：15 分钟
   - 自动检测文件变化并更新索引
   - 日志记录：`knowledge_scheduler.log`

3. **数据存储**
   - 索引文件：`datafiles/knowledge_index.json`
   - 数据结构：`KnowledgeIndex`

**技术特点**:
- 使用独立的数据结构 `KnowledgeIndex` 存储索引
- 支持定时自动扫描和手动触发
- 多维度检索（标签、摘要、关键词）
- 支持人工编辑和删除索引

## 核心节点类型说明

### 1. 条件路由节点 (route_by_workflow)
- **位置**: 招标文件解析后
- **功能**: 根据 `workflow_type` 参数路由到不同分支
- **分支**:
  - `check` → check_workflow 分支
  - `generate` → generate 分支
  - `knowledge` → knowledge 分支

### 2. 汇聚节点 (Merge Nodes)
- **图标**: 小圆圈
- **功能**: 汇聚多个并行任务的输出，然后分发到下一级任务
- **类型**:
  - 汇聚节点 1: 汇聚投标文件解析 → 分发到六个检查任务
  - 汇聚节点 2: 汇聚人工节点 → 分发到四个检索任务
  - 汇聚节点 3: 汇聚四个检索任务 → 分发到两个材料生成任务
  - 汇聚节点 4: 汇聚两个材料生成任务 → 结束

### 3. 人工节点 (Human Node)
- **图标**: 人形图标
- **位置**: 生成流程中，招标文件要求解析后
- **功能**: 人工审核点，用户可在此介入审核或调整要求
- **触发**: 触发后续自动任务（知识检索和互联网搜索）

### 4. 大语言模型节点 (Agent Nodes)
- **标注**: "大语言模型"
- **功能**: 使用豆包大模型 (deepseek-v3-2-251201) 进行智能处理
- **类型**:
  - 文档解析节点
  - 检查节点（六个维度）
  - 材料生成节点

### 5. 知识库检索节点
- **标注**: "本地知识库"
- **功能**: 使用 KnowledgeIndexer 从本地知识库检索信息
- **类型**: 商务知识库检索、技术知识库检索

### 6. 联网搜索节点
- **标注**: "联网搜索"
- **功能**: 使用联网搜索集成获取外部信息
- **类型**: 商务互联网搜索、技术互联网搜索

## 数据流转示例

### 检查流程数据流
```
输入: 招标文件 + 投标文件
  ↓
tender_doc_parse → 招标文件内容
  ↓
route_by_workflow (check)
  ↓
bid_doc_parse → 投标文件内容
  ↓
汇聚节点 1 → 分发到六个检查任务
  ↓
六个检查任务并行执行 → 各检查结果
  ↓
modification_summary → 修改建议报告
  ↓
输出: DOCX + PDF 格式的修改建议报告
```

### 生成流程数据流
```
输入: 招标文件
  ↓
tender_doc_parse → 招标文件内容
  ↓
route_by_workflow (generate)
  ↓
tender_requirements_parse → 商务要求 + 技术要求
  ↓
人工节点 → 用户审核/调整
  ↓
汇聚节点 2 → 分发到四个检索任务
  ↓
四个检索任务并行执行 → 检索结果
  ↓
汇聚节点 3 → 分发到两个材料生成任务
  ↓
commercial_material_generate → 商务材料
technical_material_generate → 技术材料
  ↓
输出: DOCX + PDF 格式的商务和技术材料
```
